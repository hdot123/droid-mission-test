## 一、定义与病根

**W-16 = 第 53 轮 24/24 worker 全灭的提交关节**：worker 会话结束时，F-1 越界检查因测试套件向 CWD 写出的 `verdict.json`/`verdict.md` 污染物而把每一个 worker 会话整体拒掉。它不是预算面问题，也不是模型行为问题——是「工单合法要求全量 pytest → 套件自身污染 CWD → F-1 严格拒绝」三环相扣的结构性缺陷。

**24/24 全灭机理**（全部引 `adversarial/round53-verify/verify-targeted.md` 的定点核验，基线 repo main = e77ada57）：

1. **工单要求全量 pytest**：第 53 轮四张工单（#790–#793）每个模块的 checks 均逐字含 `python3 -m pytest tests/ -q`（工单正文 grep：每单出现 3 次，四单一致）；领班 24 张卡（R1 12 + R2 12 重派）的 checks 字段逐字转抄，无自写额外 check；流水线模板无默认注入。工单合法，转抄合规。
2. **污染源唯一且已实锤**：`tests/test_adopt_session_outcome_w12.py` 的 3 个用例调用 `adopt(...)`，而 `scripts/team/adopt_verdict.py` 用相对 CWD 的裸 `Path("verdict.json")`/`Path("verdict.md")` 写盘（写 6 处：L141/L313/L352 写 json，L162/L327/L355 写 md；读 3 处：L334/L341/L359）。w12 测试只用 `tmp_path` 放墙与 work 目录、**无 `monkeypatch.chdir`**；对照 r52a/r52b/salvage_round2 系测试均有 chdir，唯独 w12 缺失。本地复现（git archive e77ada5 干净副本）：单跑 w12 通过 3 例但在 CWD 留下 `verdict.json`/`verdict.md`；逐个单跑其余相关文件均不产生；全量 `python3 -m pytest tests/ -q`（170 passed 2 skipped）同样留下两件污染物。
3. **F-1 拒绝面**：`.github/workflows/team.yml` worker 提交步（round-1 版 L708–L743）：L715 allowed = 卡片 `files` 集合，L716-717 追加 handoffs/status/marker 三路径，L718 scratch 仅 `{worker-prompt.txt, worker-stream.jsonl}`，L731 `extras = sorted(changed - allowed)`，L732-743 extras 非空即打印 "worker session changed files outside its card"、写 out_of_bounds 进 status.json、往 handoff 追加越界段、`sys.exit(1)`。**allowed/scratch 集合不含 verdict.\***。exit 1 发生在 `git checkout -b`/push 之前——越界即无分支、无 handoff/status 入库。
4. **全灭账**：全部 worker job 日志扫描（A–D 四 run，R1+R2 共 24 个 worker job）：24/24 全部 failure、全部被 F-1 拒绝；23 个 extras 恰为 `['verdict.json','verdict.md']`，唯一例外 C-ascii85-R2 多一件 `team/diffs/ascii85.diff`（R2 重派卡 retry_note 误导 worker 照字面写 diff 文件所致——但这是叠加伤害，不是 24/24 的共因；共因是 verdict.\* 污染）。本次结项核验已重新对 24 份日志 grep "worker session changed files outside its card"：**24 条命中，extras 分布 23×verdict.\* + 1×(verdict.\*+team/diffs/ascii85.diff)，与 verify-targeted 记账一致**。
5. **R2 注定重蹈覆辙**：重派指令「Do NOT rewrite code, just deliver」无法修复根因——越界来自测试污染，不来自 worker 行为；且 F-1 拒绝发生在推分支前，validator 报「缺 handoff/status/diff」的真因是分支根本没推上去，replan 误读为 worker 该交付 diff，形成契约错位循环。

**结论**：病根是「repo 内一处测试缺 chdir 防护」，修一处测试即可让「工单要求全量 check」与 F-1 严格性兼容——无需改工单、无需放宽 F-1（放宽 scratch 反而会放行污染源，是错误方向）。
