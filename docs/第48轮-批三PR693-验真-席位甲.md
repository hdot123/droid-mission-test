## 3. 480s 是否套到 GNU timeout；120s 是否从验收会话预算中扣出

### 3.1 480s 执行套

`run_droid_session.py` 核心路径（已读源码）：

```python
wall_sec = droid_wall_sec(wall, role, override_sec=wall_override_sec)
timeout_cmd = [
    "timeout", "--signal=TERM", f"--kill-after={KILL_AFTER_SEC}s",
    f"{wall_sec}s", *droid_cmd,
]
```

`droid_wall_sec(wall, "validator")` 在无 override、墙为 `init_wall` 形态时返回 **480**（`tests/test_budget_slice_batch3.py::test_droid_wall_reads_wall_not_literal_600`）。

**判定：** 常态验收 droid **经 GNU `timeout` 上限 480s**，不再 600s。

### 3.2 120s 预留语义

- **扣出方式：** 非「从 600 动态减 120」的单会话算术，而是 **分轨**：droid 轨硬顶 480s；采认步 `Adopt verdict` 单独 `timeout-minutes: 2`（120s 量级），并从墙 **读取** `adopt_reserve_sec` 打日志。
- **包络：** lint/墙设计坚持 `480 + 120 + kill_after ≤ job`，使验收 droid **不能**再独占 600s 墙时钟。

**判定：** 相对批二「验收 droid 默认可跑满 600s」，批三 **机制上闭合** 了「验收不能吃满 600」；`adopt_reserve` 在 adopt 步 **未另加独立计时器绑定变量**，主要靠 **droid 480 硬顶 + adopt 步 2min GHA 步限时**。

## 9. 残留边：override、缺墙、失败回退

| 场景 | 行为 | 风险 |
|------|------|------|
| 常态工单 | 无 override → `droid_wall_sec` = **480** | 低 |
| `[I8] API墙活验 A/D` 标题 | `--droid-wall-override-sec ${VALIDATOR_DROID_TIMEOUT_SECONDS:-600}` | **有意**活验注入，可回到 600 |
| 墙文件缺失 | `load_wall` 失败 → `wall=None` → `role_budget` 用 `default_budgets()` → validator **480** | 非 600 回退 |
| `droid_wall_sec` 缺字段 fallback | `.get("droid_wall_sec", 600)` 在 **合并后 dict** 上；validator 基座来自 `default_budgets` 仍为 480 | 仅当墙 **恶意清空** validator 角色且未合并基座时才危险 |
| override 参数 | `override_sec` **直接返回**，可 >480 | 仅 I8 门启用 |

`VALIDATOR_DROID_TIMEOUT_SECONDS` 仓库变量默认字符串 **`'600'`** 仍存在于 env（仅 override 分支），**不是**常态路径。

## 10. 结论与合并条件

### 结论：**有条件通过**

**成立部分（相对批二基线）：**

1. 验收 validate / validate2 **已删除常态 600s 写死**，改经 `run_droid_session` 从墙读 **480s** GNU 超时。
2. 墙上 **480 + 120 = 600** 包络有 `budget_resolve` + workflow lint + pytest 锚定。
3. 未把缩 job 15→12 当主药；未改 PAT / prod / 死亡账语义。
4. 心跳双阈值、批三 warn-only。

**条件（建议合入前或跟批补齐，本席不代为合并 #693）：**

1. **运行时证据**：至少一条 validate job 日志应出现 `wall_droid_sec=480`（或等价）且 **无**常态 `600s` GNU 行（I8 工单除外）。
2. **测试加深（可选）**：对 `run_droid_session` 做 mock subprocess，断言 `timeout_cmd` 含 `480s`（当前缺口）。
3. **领班检查点**：若产品要求「杀前必可恢复」，需步间或侧车强制写检查点，不能仅依赖 prompt + 事后扫流。
