**已坐实（本轮官方定性，机制与上条一致）**

- Factory / BYOM 侧 **同一会话**（`x-opencode-session`，如 `team-lead`、`team-validator`）存在约 **600s 总会话额度**，会话内多次模型往返**共用**该额度；领班长回复、验收员多轮慢调用可在 **GNU timeout 未到** 前先把会话额度吃光。
- A：领班两次长回复合计逼近限额，**死在计划产出之前**（K 指纹 Δ −2.1s）。
- B：三工人成功；验收员 9 次调用累满 600s（Δ −1.4s，`draft_timeout`）。

**存疑**

- 「为什么有时单轮回复特别长」—— prompt（如领班「最多 8 次 tool call」、验收「最多 12 次」）与实测调用轮次/输出 token 的对应关系，**仓库无遥测字段**；需结合 `lead-stream.jsonl` / `validator-stream.jsonl` 与网关日志再查（**需再查**）。

**已坐实（W-7 名义 vs 实际杀点）**

### 1.2 推荐改法（须保持一面墙、fail-closed）

**原则**：不靠「把 600 改成 900」抹平；用 **会话预算记账 + 输出契约门 + 采认预留** 证明墙仍判死，只是死得**可审计**。

### 2.1 问题机制

**已坐实（W-8：`field-list` 未拆信封）**

```168:175:scripts/team/foreman_run_lib.py
def parse_project_item_list(payload: Any) -> list[dict[str, Any]]:
    """Normalize `gh project item-list` JSON into a list of items (W-1)."""
    if isinstance(payload, list):
        return payload
    if isinstance(payload, dict):
        items = payload.get("items")
        return items if isinstance(items, list) else []
    return []
```
