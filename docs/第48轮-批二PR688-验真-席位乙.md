## 一、W-9 病根核对（须与既定事实一致）

### 1.1 已查实：合入前 `main` 上领班路径

在基线 `main`（`032cf0d`）上，`lead` job 的写账步为 `Patch and upload ForemanRun wall (lead)`：

- **条件**：`if: steps.dup.outputs.duplicate != 'true'`（**无** `always()`）→ 任一步失败后会话死亡则该步 **不执行**。
- **`--result`**：写死 `success`；`--produced` 写死 `true`。
- **上传**：同名 artifact 步同样 **无** `always()`。

复现方式（只读）：

```bash
git show 032cf0d:.github/workflows/team.yml | sed -n '/Patch and upload ForemanRun wall (lead)/,/Upload foreman-run wall artifact/p'
```

**机制结论**：领班失败时不存在可执行的「记失败并上传墙」步；下游 job 被 skip 后，存世 `foreman-run-${{ run_id }}` 往往只剩 `env-check` 开局快照。此与 W-2（写了但被校验路径吞掉）**同族不同因**，不得混写。

### 1.2 PR #688 对领班的修法（已查实）

`Record lead exit on ForemanRun wall (batch-2 / W-9)`：

- `if: always() && steps.dup.outputs.duplicate != 'true'`
- `RESULT` 取自 `job.status`（`failure` / `cancelled` / 默认 `success`）
- `PRODUCED` 由 `team-plan.json` 是否存在决定
- 上传步 `if: always() && … && hashFiles('foreman-run.json')`

对应 **W-9 主场景（会话/job 失败）** 已闭合。

## 三、关键机制变更（相对 `main`）

### 3.1 `workers-wall-merge`（已查实）

**合入前**：`if: always() && needs.lead.result == 'success' …` → lead 失败时 **整 job 跳过**，`chain.worker` 无法落账。

**PR**：`needs.lead.result == 'success' || needs.lead.result == 'failure'`；写账拆到独立步 `Record worker job exit…`（`always() && !cancelled()`）；上传加 `always()`。

### 3.2 `workers2-wall-merge`（已查实）

**合入前**：`needs.replan.result == 'success'` only。

**PR**：replan `success` **或** `failure` 均合并；独立 `Record worker2 job exit…` + 上传 `always()`。

### 3.3 `prep2`（已查实 · 合入前缺口）

**合入前**：`prep2` job **无** `Download ForemanRun wall`，**无** `Patch ForemanRun (prep2)` / 墙上传；备料 ROUND2 死亡时 `chain.prep2` 可长期 `unknown`。

**PR**：补 `Download ForemanRun wall`、`Patch ForemanRun (prep2)`（`PREP2_RESULT` + manifest 驱动 `produced`）、`Upload … (prep2)`。

### 3.4 `assemble`（已查实）

**合入前**：无 `chain.assemble` 退出写账；无统一 ForemanRun 收口上传步（仅 `pick_verdict_from_wall` 读墙）。

**PR**：`Record assemble exit…` 仅 `sync_assemble_exit`，`--assemble-exit`；`pick_verdict_from_wall` 仍读墙，**不**用 `assemble_chain_facts.build_facts` 回填他席。
