## 二、58-D 登记条目

**归类：第 1 类（单回合推理膨胀）worker 主型**，同时是第 2 类结构病灶（落盘排在全部推理之后 + 产出责任绑在一个会被杀的会话上）的工人席活样本。两类并记，主因记第 1 类。

机器事实（全部来自 run 45812793849 CI 工件，本地语料 `adversarial/round58-d-verify/`，verbatim 夹具在 `tests/fixtures/worker-r58d/`，sha256 对账见其 PROVENANCE.txt）：

- 死法：hslconv 工人会话死于 900s 进程墙（GNU timeout exit 124），杀死于最后的 checks 复跑步；stream 52 事件，末事件为被中断的 tool_error（"Tool execution was interrupted"），全文无 completion 事件。
- 膨胀回合（第 1 类的直接证据）：203.05s / 23,557 字符与 375.77s / 43,656 字符两个回合，合计 578.82s，占 898.68s 会话时长的 **64.41%**——单回合推理+工具跨度直接跨过整面墙。
- 落盘事实：全部 13 次工具调用中零次以 `team/handoffs/hslconv.md`、`team/status/hslconv.json` 为目标——两件协议证据文件从未写出；CI 记录的 worker delta 只有 `{"pid": "hslconv", "result": "failure"}`，无任何死因字段（该缺陷由本 mission F1 根治）。
- 产出事实：prep 在工人死后合并其分支重跑 checks **全绿**（卡片 checks 21 passed；合并态全套 384 passed, 2 skipped）——代码与测试的机器验证早已存在且独立于会话死活，作废整单的唯一原因是两件证据文件的产出责任绑在被杀会话上。
- 时间分布补证（scrutiny round-2）：r58 流事件间隔时间的 97% 落在 `tool_call` 之后——墙杀时通常有 tool 在飞，`stream_tail_marker=true` 是真实主形态；两个「膨胀」回合分别处于 system→message 与 tool_result→tool_result 区段。

登记维度（G-3 口径的工人席适配）：结论是否已形成——工序产出已完整且机器复验全绿，但会话内最后回合未及收束；recorder 调用数——validator 面度量，工人席不适用，工人席对应口径为「13 次工具调用中 0 次以两件证据文件为目标」；删失尾——末事件为被中断的 checks 复跑 tool_error。
