# 回合级熔断上游特性需求登记（droid CLI）

## 需求

**回合级熔断（per-turn circuit breaker）：对单回合（一个 assistant turn 内的推理+工具调用跨度）施加可配置预算，超限时不杀死进程，而是让回合在安全点收束并把控制权交还调用方续作。**

## 背景：死亡账第 1 类（单回合推理膨胀）

第 58 轮 D 单（run 45812793849，工人席 hslconv）死于 900s 进程墙，直接死因是两个单回合推理膨胀回合（203.05s/23,557 字符 + 375.77s/43,656 字符，合计占 898.68s 会话的 64.3%）。该类死亡的既有防线只有**进程墙**（GNU timeout，超时即 SIGTERM→SIGKILL 整进程），防线粒度与死亡粒度不匹配：杀死的是整个会话与其全部未落盘状态，而不是越界的那一个回合。

## 为何本仓不可施工（裁定理由，逐条）

1. **droid CLI 无回合预算接口。** `droid exec` 的调用面只有整会话级参数；回合是模型/agent-loop 内部概念，仓内脚本（team.yml 的 `timeout ... droid exec`）无法表达「第 N 回合超限即停」的语义。仓位只能在进程外层包 timeout，控制的粒度止步于进程。
2. **外层早杀对工件保护更差。** 本 mission M2 已确立的正确方向是「盘上产物完整性优先于退出码」：会话死活与证据完整性脱钩。外层能做的唯一「回合熔断」是把 900s 调小——那只会更早杀死会话，砍断更多落盘机会与中间状态，比现状更差；第 3 层若要成立，必须由 CLI 在回合边界主动收束（stream 落事件、会话可续），这不是外层进程控制能合成的。
3. **无续作能力。** 熔断的价值在于「熔掉回合、保留会话、续作收尾」。droid CLI 的 exec 是一次性会话：被杀即终，没有 resume/续作接口，外层无法在杀掉一个回合后让同一会话继续写完落盘件。

结论（大哥已裁）：**第 3 层（回合级熔断）不在本仓施工，登记为 droid CLI 上游特性需求**。本仓已落地的第 1+2+4 层（补卷器、模板单源+增量落盘引导、死亡上墙+归责根治）覆盖该死法的后果链；第 3 层待上游提供回合预算/安全收束/续作三能力后再立项。

## 上游需要提供的能力（立项前置）

| 能力 | 语义 | 本仓对应的接线点 |
|---|---|---|
| 回合预算 | 可配置的单回合时长/字符预算，超限在回合边界收束（非 SIGKILL 进程） | 替换/包裹 team.yml 会话步的 900s 进程墙（墙值本身维持冻结，见 P-6 口径） |
| 回合收束事件 | 熔断发生时 stream 落一个可机读的熔断事件 | delta 记录步可新增 outcome 枚举（如 turn_budget_stop），分类器 `classify_session_outcome` 扩一分支 |
| 会话续作 | 被熔断的会话可从收束点续作并完成落盘 | worker prompt 的增量落盘引导（第 2 层）提供中间状态，续作会话据此收尾 |
