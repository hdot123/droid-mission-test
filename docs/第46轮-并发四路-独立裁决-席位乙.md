## 7. A/B 失败根因（彻查）

### 7.1 现象对照

| 观测点 | A | B |
|---|---|---|
| prep 全量 pytest | 0（评论 + 证据包） | 0 |
| validate job | failure | failure |
| `Merge verdict…` step | skipped（前置 droid 步已 failure） | 同左 |
| replan | skipped | skipped |
| assemble | failure（`Fail the run when validation did not pass`） | 同左 |
| 收口 pytest 字段 | **未知**（无 `verdict.json` 合法 overall） | 同左 |

### 7.2 直接原因（日志 + artifact）

1. **Validator 子步骤** `Validator judges evidence packs only` 使用  
   `timeout … 600s droid exec … | tee validator-stream.jsonl`。
2. 两路均在约 **600s 边界** 以 **exit code 124** 结束（A：[job 135320591583](https://github.com/hdot123/droid-mission-test/actions/runs/44451928677/job/135320591583)；B：[job 135319669606](https://github.com/hdot123/droid-mission-test/actions/runs/44452030560/job/135319669606)）。
3. 下载 artifact `team-verdict-issue-478-run-44451928677`：**无** `verdict.json` / `verdict-droid.json`，仅有 **`validator-stream.jsonl`（31 行，会话起始后未 completion）**。
4. 基线 `team.yml`：无 `verdict-droid.json` 时合并步 `sys.exit(1)`；validate job 结论 **failure** → 不产出 `overall` / `failed_processes` 供下游。

### 7.3 为何 replan 被跳过（定版许可的 fail-closed）

基线 replan 条件（摘录）：

```yaml
if: needs.validate.result == 'success' && needs.validate.outputs.overall != 'pass' && …
```

**结构性失败**时 `validate.result != success` → **replan 不得触发**。这不是「工人全过却不给改计划」的编排 bug，而是 **v2.6.5 明确将「未产出判定」与「判定为 fail」分层**：前者 job 红、无 verdict，后者才进入 replan。

### 7.4 归因分类（席位乙）

| 层次 | 判断 |
|---|---|
| 工人 / 备料 | **非主因**：证据包齐、merged pytest 0、pack 内 checks 0。 |
| Validator 会话 | **主因**：600s 内未完成「≤12 次工具调用 + 写 verdict」约束（B 路 stream 显示多轮推理与大块 `Execute` 读包，时间耗尽）。 |
| 定版 / 流水线 | **次要因**：validator 预算与三路并行读包成本不匹配；无「超时后脚本兜底 verdict」；replan 门槛依赖 validate success（A2/A8 类登记与本轮现象一致）。 |

**不是**「备料假绿」：**pytest 0 与 pack checks 0 有日志与 artifact 支撑；fail 来自验收席未落盘，非 merged suite 红。**
