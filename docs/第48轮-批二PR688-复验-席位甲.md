### 1.2 lead cancelled 时 `chain.worker` 入账机制（已查实）

| 环节 | 行为 |
|------|------|
| `worker` matrix | `if: needs.lead.result == 'success' && …`（L453）→ lead **cancelled** 时 worker job **skipped** |

## 3. 打回项 3：写账/上传与 `!cancelled()`

### 3.2 workflow cancel 语义（机制说明，非打回残留）

- GitHub 在 **workflow 级 cancel** 时：`cancelled()` 为真，但 job 内标 `if: always()` 的步 **仍会执行**（与 #690 指出的 `always() && !cancelled()` 挡步问题相反）。
- 本席 **未点火** live run，故 **无** cancel 后 artifact 字节快照；对打回项 3，**静态路径 + lint 全图扫** 已足以闭合「挡落账」病根。
