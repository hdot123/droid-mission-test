## 2. 上次打回三项：逐条闭合判定

### 2.1 workers-wall-merge 须纳入 `lead` cancelled

**病根（打回前）**：`workers-wall-merge` 的 job `if` 要求 `needs.lead.result == 'success'`，上游 lead 被取消时 merge 整 job 被跳过，`chain.worker` 不落账。

**当前图（`team.yml`）**：

```yaml
if: >-
  always() && needs.lead.outputs.duplicate != 'true' &&
  (needs.lead.result == 'success' || needs.lead.result == 'failure' ||
  needs.lead.result == 'cancelled')
```

**判定**：已纳入 `needs.lead.result == 'cancelled'`；job 级未使用 `!cancelled()`。`lint_workflow_wall_exits.merge_jobs_admit_upstream_cancelled` 对该 job 通过。

**闭合**：是。

### 2.2 workers2-wall-merge 须纳入 `replan` cancelled

**病根**：`workers2-wall-merge` 仅在 `needs.replan.result == 'success'` 时运行，replan 取消后第二轮 worker 切片无法收口。

**当前图**：

```yaml
if: >-
  always() &&
  (needs.replan.result == 'success' || needs.replan.result == 'failure' ||
  needs.replan.result == 'cancelled')
```

**判定**：已纳入 `cancelled` 与 `failure`。lint 同名检查通过。

**闭合**：是。

### 2.3 写账 / 上传不得再用 `always() && !cancelled()` 挡落账

**病根**：workflow 级 cancel 时 `!cancelled()` 为假，墙写账步与 delta 上传被跳过，ForemanRun 停在旧快照。

**取证**：

| 步类 | 变更后 `if`（代表性） |
|------|----------------------|
| Record worker / worker2 delta | `if: always()` |
| Upload worker delta | `if: always()` |
| lead / replan / merge / prep2 / assemble 写账与 `Upload foreman-run` | `if: always()`（部分带 `hashFiles` 防空上传） |

全文件 grep：**不存在** 写账相关步上的 `always() && !cancelled()` 组合（v2.6.3 注释与工人 commit/失败步上的 `!cancelled()` 保留，属工序证据链路，**不在** `WALL_ACCOUNTING_MARKERS` 范围内，与打回项一致）。

`wall_accounting_steps_no_cancelled()`：**0 违规**。

**闭合**：是。
