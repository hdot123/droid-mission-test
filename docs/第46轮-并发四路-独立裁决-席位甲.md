## 5. A/B 失败根因（彻查）

### 5.1 现象链（与收口卡对照）

| 环节 | A 路证据 | B 路证据 |
| --- | --- | --- |
| prep | 评论：全量 pytest 退出码 **0**；job success | job success（~23s） |
| validate「Validator judges…」 | **failure**，~10m10s | **failure**，~10m11s |
| validate「Merge verdict…」 | **skipped** | **skipped** |
| verdict 工件 | upload 仅 stream（无 merge 产物路径） | artifact zip ~14KB；**无** `verdict.json` 机器消费链完整上传 |
| replan | skipped（assemble 失败触发的依赖链） | skipped |
| assemble 收口卡 | 总判定 **fail**；「全量 pytest 退出码：**未知**」；「验收未产出判定（validate job 结构性失败）」 | 同型（见 B run assemble failure） |

**裁定**：收口卡写「pytest 未知」**不是**备料未跑通，而是 **assemble 在无 `verdict.json` 时无法回填备料已写的 0**——属 **B7 类文案随结构性失败联动**，但根因仍是 validate 未走完机器闸，不是工人代码红。

### 5.2 直接死因：validator `droid exec` 600s 超时（exit 124）

两路 validate job 日志末端均为：

```text
##[error]Process completed with exit code 124.
```

与 `team.yml` 中 `timeout … 600s … droid exec` 包装一致（定版 **补10**：validator 会话级预算杀；本轮为 **沉默/耗尽型**——会话在读完部分证据包后未在时限内写出 `verdict-droid.json` 并完成 Merge）。

**B 路会话行为（日志）**：已读 `pytest-exit.txt`（0）、批量 `Execute` 拉取三包 checks-exit（均 0）、拉取 diff/output；随后 **无** completion 即被杀。

**A 路会话行为（日志）**：同样确认 `pytest-exit.txt = 0`、checks 全 0；validator 在细读五件对齐（尤其 status 与 checks-output 计数差异、大 diff）过程中耗尽预算——日志显示其 **未认定代码失败**，而是 **审阅策略过重** 撞 600s 墙。

### 5.3 机制层：补18 采认链断裂（Merge 步 skipped）

v2.6.5 在 validate job 内：`droid exec` 步失败 → 默认 `success()` 下 **「Merge verdict, enforce gates, verify evidence untouched」被跳过** → **不产生 `verdict.json`** → replan 无结构化 `failed[]` 输入 → **replan skipped** → assemble 只能按「验收结构性失败」收口。

这与定版第 36 轮、登记 **补18** 描述一致：**fail-closed 方向正确**（不让无 verdict 的假绿过关），但 **不能把 A/B 判为「代码未过验收员实体判定」**——两路 **没有完成验收员席位职责**，也 **没有** 进入「测试不过 → 具名 fail → replan」的定版修复回路。

### 5.4 根因归类（本席）

| 层次 | 判定 |
| --- | --- |
| 工人 / 备料 / 合并测试 | **非主因**（全量 pytest 0；三包 checks-exit 0） |
| 验收员实体判定 | **未完成**（超时，非 fail 判决） |
| 编排 / 机器闸 | **主因**（600s 预算 + Merge 无 `if: always()` 类采认；补10 + 补18 叠加重演） |
| 定版许可的 fail-closed | **部分成立**（run 红、无 PR 符合「测试/验收闸不过不开 PR」），但 **不应** 将此类失败记为「工单交付物未达规格」 |

**重要**：若仅读收口卡或 run 红绿，会 **误判为质量失败**；证据链支持 **「主路径全绿、死于验收席预算与采认链」**（与第 36 轮镜像判语同族，但本轮 validator 甚至未产出草稿 JSON）。

### 5.5 若有人主张「其实代码是对的」

本席 **不否认** 备料层强烈暗示三模块合并可过；但在领班制定版下，**未产生可被 assemble 消费的 `verdict.json` + overall 与 pytest 闸** 即 **流程未通过**，必须 **驳回**，不能为圆场改为「通过」。补救应走 **原样重跑 / 验收席预算或读包策略治理**，而非将 A/B 标绿。
