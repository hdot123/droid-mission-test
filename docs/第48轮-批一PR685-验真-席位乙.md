## 4. 病根与 PR 是否根治

### 4.1 W-8（field-list 信封当 list 用）

**main 证据**（`git show main:scripts/team/project_state_write.py`）：

```python
fields = json.loads(fr.stdout or "[]")
field_id, option_id = pick_status_option(fields, status)
```

当 gh 返回 `{"fields":[...], "totalCount": N}` 时，`pick_status_option` 对 dict 迭代导致 **AttributeError**。

**PR 证据：**

- 路径：`parse_project_field_list` → `fetch_project_fields` → `pick_status_option(fields, …)`（`tests/test_gh_project_parse_contract.py::test_w8_bare_dict_breaks_pick_status_without_parse` / `test_w8_pick_status_after_parse`）。

**判断：** 写板路径 **根治**（拆盒 + 契约测试锁死）。

### 4.2 W-1（item-list 分页 / 假阴性）

**main 证据：** `item-list` 固定 `"--limit", "200"` 单次调用；`parse_project_item_list` 仅拆信封，无 totalCount 跟进。

**PR 证据：** `scripts/team/gh_project_parse.py::fetch_project_items`

1. 首次 `--limit` = `page_size`（默认 100）；
2. 若 `totalCount` 为 int 且 `len(items) < totalCount`，再以 `--limit min(totalCount, 10000)` 调用；
3. 若仍截断且 `total > 10000`，`RuntimeError`（fail-closed）。

**契约测试：** `test_item_list_pagination_refetch`：mock 首次返 `item_list_truncated_page.json`（totalCount=250，items=1），二次 limit=250 返满 250 条；断言 `calls == [100, 250]`。

**判断：**

| 维度 | 结论 |
|------|------|
| 相对 main 固定 200 | **消除** `200 < totalCount ≤ 10000` 类假阴性（在 gh 按高 limit 聚合前提下） |
| 是否「真翻页」 | **否**；是 **抬高 limit 的二段式**，非 per-page cursor |
| totalCount 缺失 | **尚未根治** 潜伏尾（`unwrap_item_list_envelope` 对无 totalCount 的 dict 不触发重拉） |
| totalCount > 10000 | **fail-closed**，非静默假阴性 |

归类：**部分根治 + fail-closed 上限**，批一批内可接受；不宜宣称为「消灭一切分页假阴性」。

### 4.3 field-list 轻微截断

`fetch_project_fields` 默认 `limit=200`，逻辑与 item-list 类似（totalCount 比对后二次抬高 limit）。对 mission board 字段规模（fixture `totalCount: 1`）足够；极大字段表依赖 gh 聚合与 10000 cap。
