## 1. 三类死因 — 独立核实

### 1.1 死因一（A/B · 会话/预算 · W-7）

| 主张 | 本席核实 | 结论 |
|------|----------|------|
| 墙名义 `validator 480+120`、lead `600` | `default_budgets()` 与方案引用一致 | **站住** |
| workflow 验收 droid 仍 **600s** GNU timeout | `team.yml` L1343–1348；仅 I8 标题可改 `VALIDATOR_DROID_TIMEOUT_SECONDS` | **站住** |
| 供应商同会话 ~600s 共用额度 | 仓库无遥测；属**外部机制**，方案标「已坐实（官方定性）」略强，施工应标 **需再查/活验钉死** | **有条件站住** |
| `session_outcome` 墙字段缺失 | `init` 预算无该字段；但 **`adopt_verdict.py` 采认时会 patch `budgets.session_outcome`**（validator 路径） | **部分推翻方案表述**：不是完全「未写入」，而是 **仅 validate 采认链写入、lead/replan 无** |
| `compute_validate_conclusion` 读 `session_outcome` | L25–30：`timeout`/`droid_failed`/`missing_output` → job failure | **站住**；但 **供应商额耗尽若 exit≠124** 未必进入上述枚举 |
| 领班 droid **无** `droid-exit.txt` | lead L198 **无** `set +e` + exit 落盘；validate 有（L1342–1349） | **站住**（方案未强调 lead/replan 对称缺口） |

**漏网 / 误定论风险**

- 仅把 GNU `timeout` 从 600 改为 480 **不能证明**闭合供应商总会话额；若杀点仍在 ~600s 供应商侧，墙可能仍只有模糊的 `droid_failed`，与 `session_budget_exhausted` 区分方案**缺可测判据**（何字段、何 exit、何 stream 指纹）。
- validate job `timeout-minutes: 15`（900s）：480+120+prep+adopt 在纸面上够，但若 prep 边缘拖长或 supplier 在 GNU 杀前断会话，**仍可能**在 adopt 前耗尽；方案 P0「`min(droid_wall_sec, job_remain)`」**未给出** lead job 15min 与 droid+plan 步的分配算式，活验可能反复踩 job 墙而非 droid 墙。

## 2. 一面墙 / 逃逸

- **未提议分墙或墙外 verdict 源** → 认可。
- **风险点（须施工收窄）**：
  - `assemble_chain_facts.build_facts` 可用 **env `*_RESULT`** 回填 `chain`（L125–129），若 assemble 引入该脚本却**未禁 env 注入**，与 I2「禁止 needs.*_RESULT 选路径」精神冲突。实施须：**仅允许在 chain 仍为 unknown 且数据来自 foreman-run artifact 内字段**，或完全不用 env 映射。
  - synthetic overall 不得让 `pick_verdict_from_wall` 在 `artifacts.*.complete=false` 时强行 pass — 应新增 **assemble 专用「上游失败收口」步**，写 `closeout`/`validation.overall=fail` 并驱动写板 `overall=fail`，与 pick 失败路径并列，而非放松 B2。

## 4. 必改（实施 PR / 方案修订）

1. **W-1 分页**：删除或改写对 `cursor`/`--after` 的依赖；施工前用本机 `gh project item-list --help` 定稿（本席：`--query` 过滤 issue 为可执行路径）。
2. **assemble 上游失败路径**：与 pick fail-closed **并列** 的收口设计须写清：`board_write` 的 `OVERALL`、最终评论、`closeout.run_must_fail` 在 **无 verdict artifact** 且 **chain.lead= failure** 时如何取值；不得仅在文档中写「synthetic overall」而无墙字段契约。
3. **`assemble_chain_facts` 若入链**：禁止通过注入 `LEAD_RESULT` 等 env 绕过 I2；或 assemble 根本不使用该 env 分支。
4. **lead + replan**：与 validate 对称捕获 droid 退出码并写入墙（`session_outcome` 或 `chain.lead`/`chain.replan` facts）；否则 W-9/W-7 只修一半链。
5. **schema**：新增 `summary_code` / `completion_status` / `adoption_error` 取值须在 `foreman-run.v1.schema.json` 同步，`test_foreman_wall_contract.py` 覆盖。
6. **W-9 文案**：施工 PR 不得写死「写账崩溃」；P0 硬门落地后 run 工件对比 env-check vs lead-finalize artifact **版本数** 作为活验判据（方案 §3.4 已有，须升为必改验收）。

## 5. 建议改（不挡有条件通过）

1. 将「`session_outcome` 半成品」改为准确表述：**validator 采认已写，lead/replan 未写，budgets 与 workflow timeout 不一致**。
