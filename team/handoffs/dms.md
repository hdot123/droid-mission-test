# Handoff — dms（子流程 #424，工单 #410 第四十三轮 D）

## 请求了什么

工单 #410 第一部分：新增 `dms.py`（十进制度数 ↔ 度分秒）与 `tests/test_dms.py`，只新增、不改存量，仅标准库，不依赖其他流程的文件。验收要点共 9 条，逐字：

- `to_dms(48.8584) == (48, 51, 30.24)`
- `to_dms(-118.2437) == (-118, 14, 37.32)`
- `to_dms(0) == (0, 0, 0.0)`
- `from_dms(48, 51, 30.24) == 48.8584`
- `from_dms(-118, 14, 37.32) == -118.2437`
- `from_dms(0, 0, 0) == 0.0`
- `from_dms(0, 60, 0)`、`from_dms(1, -1, 0)` 抛 ValueError
- `48.8584`、`-118.2437` 往返恒等（`abs(...) < 1e-9`）

行为规格：`to_dms` 符号只进度分量（南纬／西经为负度，分秒非负），秒最多 6 位小数并四舍五入、进位到分／度；`from_dms` 要求 `m ∈ [0,59]`、`s ∈ [0,60)`（`s == 60.0` 表示进位、允许），否则 ValueError。

## 做了什么

## 校验者必须注意的点

1. **`from_dms` 的负数处理与工单字面公式不一致，这是刻意的。** 工单写「返回 `d + m/60 + s/3600`」，但同时要求 `from_dms(-118, 14, 37.32) == -118.2437`（用 `==`，非容差）。字面实现对负度数算出的是 `-117.7563`（误差 0.487），**不满足验收**。实现改为「先合绝对值、最后整体加符号」，即 `-(|d| + m/60 + s/3600)`；它与 `d + m/60 + s/3600` 在 `d < 0` 时**逐位相同**（同一批加法、同序，最后取负），因此 `from_dms(-118, 14, 37.32) == -118.2437` 与 `from_dms(48, 51, 30.24) == 48.8584` 都精确成立。正数、`d == 0` 的情形与字面公式完全一致（`0.0` 输出也保持 `-0.0` 不出现）。验收若只按 9 条要点判，两条等式均为精确 `True`。
2. `to_dms`：`to_dms(0) == (0, 0, 0.0)` 要求秒是 float `0.0`（Python 里 `0 == 0.0` 为真，且实现确实返回 float）；分、秒恒非负，符号只在度。
3. `from_dms` 校验：`m ∉ [0,59]` 或 `s ∉ [0,60]` 抛 ValueError；`s == 60.0` 合法（等价于向分进位），`s > 60` 抛 ValueError。
4. 新增文件共 4 个：`dms.py`、`tests/test_dms.py`、`team/handoffs/dms.md`、`team/status/dms.json`。
