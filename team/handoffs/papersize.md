# Handoff: papersize (sub-issue #908)

## What was requested

Process card #908 under work order #901 (round 57, concurrent card A): implement the ISO 216 A-series paper-size module as two independent deliverables, touching only two new files:

- `papersize.py` with `paper_size(n: int) -> tuple[int, int]` (returns `(short, long)` in mm for A0..A10) and `paper_area(n: int) -> int`.
- `tests/test_papersize.py` covering every acceptance point.

Hard constraints: standard library only; no imports of other project modules; only add these two files; do not modify any existing file; sizes must be **generated by the halving rule** (from A0 = 841×1189: new short = floor(old long / 2), new long = old short), never hardcoded per-n lookups.

Input validation: `n < 0` or `n > 10` raises `ValueError`; non-int `n` (including `bool`) raises `TypeError`.

## What I did

- Created `papersize.py`:
  - `_check_n` validates type first (bool rejected explicitly since `bool` subclasses `int`), then range.
  - `paper_size` iterates the halving rule from `(841, 1189)` exactly `n` times via `long // 2` (floor semantics) — no table.
  - `paper_area` delegates to `paper_size` and multiplies, so the area/size consistency property holds by construction.
- Created `tests/test_papersize.py` with 14 test cases covering each acceptance point:
  - full ISO table comparison for all n = 0..10 (including `paper_size(0) == (841, 1189)` … `paper_size(10) == (26, 37)`),
  - an independent halving-rule regeneration test (proves generation, not lookup),
  - `paper_area(0) == 999949`,
  - `paper_area(n) == paper_size(n)[0] * paper_size(n)[1]` for every n,
  - `ValueError` on -1 and 11 (both functions),
  - `TypeError` on `4.0`, `"4"`, `True` (both functions).

## What the validator must pay attention to

- Return order is `(short side, long side)`, not `(long, short)` — e.g. `paper_size(0) == (841, 1189)`.

- `bool` is rejected before the range check (`isinstance(n, bool)` first), so `paper_size(True)` raises `TypeError`, not the range `ValueError`.
